## 一、什麼是 NUMA？

**NUMA (Non-Uniform Memory Access)** 不是一個選擇性的最佳化，而是現代多插槽 (multi-socket) 與多晶片 (multi-chip) CPU 的基本特性。記憶體在實體上分散於各 CPU 插槽與內部 chiplets，存取延遲取決於計算發生處與記憶體的相對位置。

### NUMA 的基本原則

```
CPU Socket 0          CPU Socket 1
┌──────────────┐     ┌──────────────┐
│  Local RAM    │     │  Local RAM    │
│  ← 快速存取  │     │  ← 快速存取  │
│──────────────│     │──────────────│
│  Remote RAM   │ ←──→ │  Remote RAM   │
│  ← 較慢存取  │     │  ← 較慢存取  │
└──────────────┘     └──────────────┘
```

- 每個 CPU socket 有自己的直接連接記憶體 → **Local access = 快速**
- 存取其他 socket 的記憶體 → **Remote access = 明顯較慢**
- 作業系統將此佈局揭露為 **NUMA nodes**

> **生活比喻**：想像 NUMA 就像幾個相鄰的城市。在自己的城市裡用 local roads 移動很快；去另一個城市需要上高速公路或火車，會花更長的時間。連線存在且可靠，但距離和共享路線會引入延遲。

## 二、壓力測試結果

Vertica 在配備 **雙 AMD EPYC 處理器**、大容量記憶體的 hyperscale 伺服器上進行了壓力測試，預設 NUMA 配置暴露了 8 個 NUMA nodes。

| 配置 | 吞吐量倍數 | CPU 使用量 |
|------|-----------|-----------|
| 1 Vertica node / 1 server | **1×** (基準) | 相同 |
| 2 NUMA-bound nodes / 1 server | **1.93×** | 相同 |
| 4 NUMA-aligned nodes / 1 server | **3.19×** 🏆 | 相同 |

> **關鍵發現**：單一 Vertica node 在約 50 核心後就無法有效擴展，第二顆 CPU 大部分處於閒置狀態。透過 NUMA-aware 多節點部署，**相同的 CPU 用量**下吞吐量提升了 **3.19 倍**。

## 三、v26.2 NUMA 核心功能

Vertica v26.2 引入了以下 NUMA 功能（Beta）：

| 功能 | 說明 |
|------|------|
| **每實體伺服器多個 Vertica nodes** | 每個 node 綁定到自己的 NUMA CPU 與記憶體資源 |
| **自訂連接埠** | 每個 Vertica node 和 NMA 可設定獨立 port |
| **NUMA node 指派** | 透過 `vertica_cluster.yaml` 配置 |
| **VCluster CLI 支援** | 支援 NUMA 多節點的 add/remove/list 操作 |

### 與 Compute Node 架構的關係

v26.2 的 NUMA 部署模式與 Vertica **Compute Node 架構** 和 **NUMA-aware subcluster 設計** 自然契合：

- Compute Nodes 是輕量級、專注於執行的節點，不維護完整 global catalog
- 透過移除完整 catalog 載入、commit 參與和全域鎖競爭，compute nodes 可以快速啟動、彈性擴展
- 結合 NUMA-aware 放置後，多個 compute nodes 可以高效地共存於同一實體伺服器

## 四、硬體規格建議

### CPU

| 項目 | 建議 |
|------|------|
| **處理器** | AMD EPYC 或 Intel hyperscaling 系列，16–256 cores/socket |
| **雙插槽** | 每個 socket 視為獨立 NUMA domain，需最小化跨 socket 存取 |
| **SMT/HT** | **必須關閉**（不為分析工作負載提供比例增益，反而引入排程效率問題） |

### RAM

| 項目 | 建議 |
|------|------|
| **容量** | 96–512 GB DDR4/DDR5 per server |
| **每核心** | 至少 8 GB/core，高並發建議 12–16 GB/core |
| **通道** | 滿插記憶體通道，均勻分配 DIMM |

### 儲存

| 項目 | 建議 |
|------|------|
| **類型** | NVMe SSD（primary storage + depot） |
| **RAID** | **避免使用硬體 RAID 控制器** → 使用 OS 級 JBOD |
| **PCIe lanes** | 確保每 socket 有足夠 PCIe lanes，不過度訂閱 |

### 網路

| 項目 | 建議 |
|------|------|
| **頻寬** | 每個 Vertica node 約消耗 2.5 Gbit/s，3+ nodes 建議 25–100 GbE |
| **IP** | 必須使用**靜態 IP**（Vertica 不支援動態 IP） |
| **隔離** | 專用 switch 或 VLAN，相同 subnet |

## 五、多節點部署範例

以下步驟展示如何在單一主機上部署多個 NUMA-aware Vertica nodes。

### Step 1：建立目錄

```bash
$ mkdir /data/vdb/v_vdb_node0010_catalog
$ mkdir /data/vdb/v_vdb_node0011_catalog
$ mkdir /data/vdb/v_vdb_node0012_catalog
$ mkdir /data/vdb/v_vdb_node0010_data
$ mkdir /data/vdb/v_vdb_node0011_data
$ mkdir /data/vdb/v_vdb_node0012_data
```

### Step 2：建立節點定義

```sql
=> CREATE SUBCLUSTER sc;

=> CREATE NODE v_vdb_node0010 IS HOSTNAME '190.104.56.103'
   DATAPATH '/data/vdb/v_vdb_node0010_data'
   CATALOGPATH '/data/vdb/v_vdb_node0010_catalog'
   SUBCLUSTER sc PORT 8555;

=> CREATE NODE v_vdb_node0011 IS HOSTNAME '190.104.56.103'
   DATAPATH '/data/vdb/v_vdb_node0011_data'
   CATALOGPATH '/data/vdb/v_vdb_node0011_catalog'
   SUBCLUSTER sc PORT 8557;

=> CREATE NODE v_vdb_node0012 IS HOSTNAME '190.104.56.103'
   DATAPATH '/data/vdb/v_vdb_node0012_data'
   CATALOGPATH '/data/vdb/v_vdb_node0012_catalog'
   SUBCLUSTER sc PORT 8559;
```

### Step 3：啟動 Vertica 程序

```sql
=> SELECT Vertica_start_command('v_vdb_node0010');
-- 執行回傳的命令，然後重複
=> SELECT Vertica_start_command('v_vdb_node0011');
=> SELECT Vertica_start_command('v_vdb_node0012');

-- 驗證
=> SELECT name, address, clientport FROM vs_nodes;
```

### Step 4：準備接受查詢

```sql
=> SELECT reload_spread(true);
=> SELECT rebalance_shards('sc');
```

### 卸載節點

```sql
=> ALTER NODE v_vdb_node0010 IS EPHEMERAL;
=> ALTER NODE v_vdb_node0011 IS EPHEMERAL;
=> ALTER NODE v_vdb_node0012 IS EPHEMERAL;
=> SELECT rebalance_shards('sc');
=> DROP NODE v_vdb_node0010;
=> DROP NODE v_vdb_node0011;
=> DROP NODE v_vdb_node0012;
=> SELECT reload_spread(true);
=> DROP SUBCLUSTER sc;
```

| 面向 | 傳統單 node/伺服器 | NUMA-aware 多 node/伺服器 |

| **CPU 利用率** | 50% 以下（第二顆 CPU 閒置） | 接近 100% |
| **吞吐量** | 1× 基準 | **3.19×** |
| **基礎設施成本** | 高 | **降低 66%** |
| **擴展方式** | 增加伺服器 | 充分利用現有伺服器 |
| **適用硬體** | 通用 | 現代 multi-socket hyperscale 伺服器 |

## 七、版本與限制

- **首次引入**：Vertica **v26.2 Beta**
- **VCluster CLI**：支援基本的 add/remove/list nodes 操作
- **未來版本**：預計 v26.3 支援動態節點增減；完整生命週期管理將在後續版本提供
- **不支援**：動態 IP、硬體 RAID 控制器、SMT/Hyper-Threading

> **注意**：本功能為 Beta 階段，不建議直接用於生產環境。上述部署流程為展示用，實際操作請參考 Vertica v26.2 官方文件。
