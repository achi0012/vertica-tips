## 1. What is NUMA?

**NUMA (Non-Uniform Memory Access)** is a fundamental property of modern multi-socket CPUs. Memory is physically distributed across sockets, and access latency varies depending on where computation occurs relative to memory.

```
CPU Socket 0          CPU Socket 1
┌──────────────┐     ┌──────────────┐
│  Local RAM    │     │  Local RAM    │
│  ← Fast       │     │  ← Fast       │
│──────────────│     │──────────────│
│  Remote RAM   │ ←──→ │  Remote RAM   │
│  ← Slower     │     │  ← Slower     │
└──────────────┘     └──────────────┘
```

- Each CPU socket has local memory → **Fast access**
- Accessing another socket's memory → **Significantly slower**
- OS exposes this as **NUMA nodes**

## 2. Stress Test Results

Tested on dual **AMD EPYC** processors with 8 NUMA nodes per server.

| Configuration | Throughput | CPU Usage |
|--------------|-----------|-----------|
| 1 Vertica node / server | **1×** (baseline) | Same |
| 2 NUMA-bound nodes | **1.93×** | Same |
| 4 NUMA-aligned nodes | **3.19×** 🏆 | Same |

> Single Vertica node doesn't scale beyond ~50 cores. With NUMA-aware deployment, **3.19x throughput** using the same total CPU.

## 4. Hardware Requirements

### CPU
- AMD EPYC or Intel hyperscaling (16–256 cores/socket)
- **SMT/HT must be disabled** (no benefit for analytic workloads)

### RAM
- 96–512 GB DDR4/DDR5 per server
- At least 8 GB/core (12–16 GB recommended for high concurrency)

### Storage
- **NVMe SSD** (avoid hardware RAID controllers → use JBOD)
- Adequate PCIe lanes per socket

### Network
- ~2.5 Gbit/s per Vertica node, **25–100 GbE recommended** for 3+ nodes
- Static IPs only (no dynamic IP support)

## 5. Multi-Node Deployment

### Step 1: Create Directories

```bash
$ mkdir /data/vdb/v_vdb_node0010_catalog
$ mkdir /data/vdb/v_vdb_node0010_data
```

### Step 2: Create Nodes

```sql
=> CREATE SUBCLUSTER sc;
=> CREATE NODE v_vdb_node0010 IS HOSTNAME '190.104.56.103'
   DATAPATH '/data/vdb/v_vdb_node0010_data'
   CATALOGPATH '/data/vdb/v_vdb_node0010_catalog'
   SUBCLUSTER sc PORT 8555;
```

### Step 3: Start Processes

```sql
=> SELECT Vertica_start_command('v_vdb_node0010');
-- Execute returned command, repeat for each node
```

### Step 4: Prepare for Queries

```sql
=> SELECT reload_spread(true);
=> SELECT rebalance_shards('sc');
```
